# Audition in context

Resolve the user's listening question, intended subject and comparison scope
through [exploration](../../bitwig-explore/SKILL.md). Read the relevant track,
clip, routing and automation from the current project. Use the score, cues or
PERFORMANCE.md when they explain the musical function. Choose a passage where
the difference matters. A candidate may need both an exposed entrance and a
passage in which it supports another part.

| Context | Audition route |
| --- | --- |
| An existing Arranger passage, track, or mix | Play the resolved passage through [session actions](../../bitwig-explore/references/session-actions.md), or [render the exact range and channels](../../bitwig-explore/references/audio-export.md) for review. A listening-only request needs no new devices or clips. |
| Alternatives already present in the project | Use the existing alternate tracks, clips, or receiver choices that the user has put in scope. Select or switch through qualified session actions. When the comparison uses an existing Instrument Selector, use the [manual choice procedure](../../bitwig-explore/references/session-actions.md#audition-an-existing-manual-selector). |
| A new musical candidate needs a temporary playing surface | Use the destination the user requested or an existing safe surface suited to the layout. For a Launcher prototype, resolve the exact track and scene, use native `launcher read` for an empty slot, and send creation or editing to [bitwig-edit](../../bitwig-edit/SKILL.md). Independently reread it, audition via session actions, then return the track to Arrangement. For an authorized in-place Arranger experiment, [checkpoint the saved project](../../score-intake/references/project-layout.md#experimental-project-backups), retain complete original content, and use the owning edit operation. |

Treat the selector and Launcher as options. When a candidate needs a receiver
assignment or new musical content, invoke its owning skill only within the
authorized scope. If the live layout cannot support the requested comparison,
report the affected candidate and continue with the available ones.

For a comparison, keep the source notes, passage, mixer context and export
options common except for the intended variable. Preserve the native renders.
When loudness could bias judgment, compare level-matched audition copies and
label them. A solo stem reveals the attack and decay. An ensemble render can
answer whether that sound takes the intended place in the mix. Report what
was heard, what was measured, and which context the evidence covers.

For a temporary comparison, restore the previous playing source and any
temporary changes you made, then verify them. Apply a candidate only when the
user approves or delegates application. When a repair transfers to other
occurrences, qualify them by musical function, score markings and native
notes. Include transpositions or variants that serve the same function.
Preserve adjacent figures and unrelated shared-source aliases. Send exact
Arranger clip paths and approved changes to editing. For a Launcher transfer,
align beat coordinates and compare native readback directly with the approved
candidate, including numeric values. Save and verify when delivery calls for it.
