# Compose in Bitwig

Use the [workflow stories](references/workflow-stories.md) for cross-skill
handoffs, artifact ownership and readiness. For an isolated operation, go
directly to its owning skill.

| Requested result | Procedure |
| --- | --- |
| Admit and orchestrate a score, propose or apply cue-led expression, or realize sung phrases | [Score and performance](references/score-and-performance.md), including the orchestration checklist for a new rendition |
| Compose a part against the arrangement or extend the piece | [Compose and revise](references/compose-and-revise.md) |
| Hear a passage, compare candidates, or audition and apply a repair | [Audition in context](references/audition.md) |
| Analyze the current native performance | [Read back the arrangement](references/readback.md) |

Start from the requested musical result and the intended saved project (or
the supplied score for new work). For a contextual request, resolve the
selected object and its owner through [exploration](../bitwig-explore/SKILL.md).
Carry the project path, qualified native paths, relevant arranger beat/range,
musical occurrence and preservation scope into the next owner. Refresh
operation-specific authority immediately before mutation. Resolve again if
the project, ownership, name, or placement changed.

Run only the stages needed for the result. Resume at the first missing proof.
For score-to-playable delivery, account for each required musical effect using
the [score and performance checks](references/score-and-performance.md#turn-the-score-into-a-playable-ensemble)
before calling the arrangement complete.
When an owner returns a refusal or an unknown outcome, use its readback and
reconciliation procedure before dependent edits. Continue independent work.
Use the [shared session actions](../bitwig-explore/references/session-actions.md)
for seek, audition, visibility, and Save. State which results have fresh native
readback, saved persistence, listening evidence and, where requested, actual
approval.
