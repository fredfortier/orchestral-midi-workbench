# Library preprocessing transaction

`kontakt-ctl --json batch-resave TOP_LEVEL_X_FOLDER [--check]` is separate from
hosted receiver loading. Its result proves processing, not musical capability.

## Scope and completion

Admit one literal directory directly under Wine's `X:` mapping. Reject traversal,
redirects, wildcards and empty inventories. Launch and retain one standalone PID;
resolve dialogs and verify the exact selected native folder before submission.
Serialize preprocessing transactions; never target a hosted/foreign player.

Success requires the unchanged initial `.nki`/`.nkm`/`.nkb` inventory rewritten,
nonempty exclusively readable outputs, no outstanding owned dialogs and clean
owned-process exit 0. Inactivity, partial writes, unresolved samples, timeouts and
forced cleanup fail. Cleanup may close/terminate only the retained owned process;
it must not manufacture completion. Do not retry an uncertain partial operation.

## Path-based processing receipt

After clean completion, atomically publish `.kontakt-ctl-batch-resave.json`, schema
`kontakt-ctl.batch-resave/v3`: target folder, covered relative filenames,
expected/rewritten counts, completion time, exit code and evidence-log path.
Reuse checks covered paths and successful outcome, not player/patch hashes.
The implementation also reads compatible v2 coverage without requiring its hashes.
`--check` never launches Kontakt; an ordinary covered repeat also skips launch.

Documented completed historical folder processing may be reused through intake;
missing modern receipt formatting alone is not grounds to rewrite a library.
Failed or unknown processing requires reconciliation, not an invented receipt.
Back up original instrument files before authorized preprocessing; never promote
real-library coverage from a disposable fixture's receipt.

## Verification

Ephemeral Windows checks cover path/ownership admission, native folder readback,
completion, failure cleanup and receipt reuse. Live qualification must independently
observe exact target, complete rewrites and process exit on disposable files.
Runtime invocation and recovery diagnostics are in [README.md](README.md).
